# AirControl 手部识别可行性论证执行指令

将下面内容交给承担本轮论证的执行 AI。完整方案位于同目录的 `hand_model_feasibility_plan.md`。

```text
请在 D:\airControl 执行手部识别路线可行性论证。先完整阅读
D:\airControl\docs\hand_model_feasibility_plan.md，并遵循适用的仓库指令。

目标是用可复核证据判断 RTMPose-m Hand5 及 Distill、WiLoR、YOLO26
手部专用模型、SAM 3D Body、Hand-4DGS 是否适合本项目。不得预设必须换模型。
分别给出研究引用、本地集成和随产品分发三个层面的结论。

先执行 P0 和 P1：
1. 检查 git 状态、当前硬件、模型、录像位置、配置生效值和真实调用链。
   保留用户的 config.json 修改和既有未跟踪文件，不重置工作区。
2. 建立实验隔离。新依赖使用单独环境，不覆盖现有 onnxruntime-directml。
3. 对所有路线核实原始论文、代码、精确权重、版本、访问及许可条件，
   建立 evidence.csv；论文结论与自己实测分开。
4. 先固定评测协议和统一输出，再实现候选适配器。
   修正现有脚本中预测帧计数、回放时钟、完整按钮行为和事件匹配口径，
   新评分器应单独版本化，旧结果标记为 legacy。
5. 找不到独立真人数据时，交付采集清单和标注工具，继续其他可完成工作。
   不用模型输出当真值，不声称没有做过的实验已经通过。

然后按 P2 至 P5 的门槛推进：先做所有可运行路线的小样本筛选，
再分原始关键点、统一后处理、完整控制三个层次对照；最多两条路线进入
完整模式验证。RTMPose 原版与蒸馏版分别测试。Windows 原生部署与
Linux/WSL 离线验证分开结论。Hand-4DGS 等读取未来帧的算法计入等待延迟。

正式测试集按参与者和会话隔离，测试前冻结参数。只在开发集调优。
模型不提供手势标签时，必须核验 Victory、ILoveYou 等标签依赖；
仅有 21 个点不算完整替换成功。若保留 MediaPipe 并行分类，披露其成本。

离线模式使用假鼠标、键盘和画布控制器，不向真实桌面发送操作。
不改变生产默认配置，不安装到生产环境，不上传录像，不使用付费云资源。
单路线部署连续阻塞半天后，记录证据并转去其他路线，不无限修环境。

按方案第 12 节交付运行命令、版本哈希、原始预测、事件日志、分场景指标、
失败样例和最终报告。指标缺失填未测，不填零。阈值是待冻结的工程目标，
不是既成结论；正式测试揭盲后不得改门槛以追求通过。

每条路线最终选择：建议默认采用、建议限定场景采用、建议离线辅助、
仅作研究参考、暂不采用、无法判定。每项结论附适用边界和可复核证据。
如果只得到个人小样本结果，明确限制结论，不宣称通用默认替换成功。
```

若交给多个执行 AI，先由一个 AI 完成方案中的 T0 契约和协议，再分配 T2 至 T5；统一评审由 T6 使用冻结结果完成。执行层不得同时修改共享基类和生产配置。
